# Hikari Studio 第二阶段路线图

## 产品原则

Hikari 的差异化不是“编辑器里放一个聊天框”，而是让 Agent 具备完整制作闭环：理解项目、规划修改、调用受限工具、预览结构化差异、运行游戏诊断、等待用户确认、应用并支持撤销。

用户只需要配置 OpenAI 兼容 API URL、API Key 和模型名称。API Key 进入 Windows Credential Manager，不写入项目、配置文件或日志。

## 六周交付节奏

### 第 1 周：流程控制与诊断

- 变量赋值、条件判断、跳转、调用和返回 Block。
- 编辑器预览、Web 运行时和 Ren'Py 导出行为对齐。
- 无效片段引用、空选择支和无限循环诊断。
- 流程 Block 属性检查器和可视化摘要。

当前状态：第一批流程 Block 与诊断器已实现；已建立 Vitest 正式测试基线，首批 19 个用例覆盖条件、分支、调用栈、无限循环保护、存档迁移、回滚与主要诊断类型，仍需继续扩展所有 Block 和 UI 集成覆盖。

### 第 2 周：角色与舞台

- 角色显示、隐藏、站位和多角色舞台状态。
- 表情切换、进入/退出动画和遮挡顺序。
- 背景、CG、转场、镜头移动、缩放和震动。
- 舞台状态写入存档并支持回滚。

### 第 3 周：声音与演出

- BGM、音效、语音分轨控制。
- 循环、淡入淡出、音量和停止指令。
- 自动播放、快进、已读状态、文本速度和历史记录。
- 音频资源引用检查和试听。

### 第 4 周：存档与完整运行时

- 存档、读档、快速存档和自动存档。
- 游戏设置、流程回滚和历史重放。
- SaveGame 版本迁移和损坏恢复。
- 独立预览窗口与运行时错误定位。

### 第 5 周：AI 制作 Agent 1.0

- 项目读取工具：章节、角色、变量、素材和引用关系。
- 创作工具：创建片段、添加/修改 Block、设置变量和分支。
- 诊断工具：缺失引用、不可达片段、死循环和角色一致性。
- 每次修改生成结构化差异，用户确认后进入 Command 历史。
- 支持 OpenAI、Azure OpenAI 和 OpenAI 兼容接口。

当前状态：API 配置、Credential Manager、结构化计划预览、确认应用和撤销链路已实现第一版。

### 第 6 周：UI 补全与稳定化

- 全局搜索真正支持定位和替换。
- 运行设置、预览设置、通知中心和项目切换器接线。
- 叙事地图显示真实跳转边并支持画布缩放、移动和自动布局。
- 角色表情管理、删除、引用查询和素材批量操作。
- 持久历史记录、独立预览和 Windows 构建入口。
- 完整桌面回归、性能测试和示例工程通关。

## Agent 分级

### L1 制作助手

根据自然语言生成结构化制作计划。用户逐项审查后应用。当前正在实现。

### L2 工具型 Agent

Agent 可以多轮调用项目查询、脚本编辑、诊断和预览工具，但不能绕过权限边界。每轮工具调用可观察、可取消、可回滚。

### L3 制作统筹

根据大纲拆章节、维护角色设定、检查分支覆盖、生成待办、调用 TTS/图片服务并执行构建前检查。外部素材生成必须单独授权并显示成本预估。

## 必须坚持的安全边界

- Agent 永远不能直接写任意文件，只能调用注册工具。
- 删除、覆盖、外部上传和付费生成必须再次确认。
- API Key 不进入 React 状态持久化、项目数据、崩溃报告和日志。
- 模型输出必须通过 Schema、引用和权限三层校验。
- 所有项目修改必须生成差异并支持撤销。
- Web 游戏和导出包不得包含编辑器 AI 配置。
